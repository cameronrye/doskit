## Overview

DosKit is a modern web application that enables users to run classic DOS applications and games directly in their browser without any installation. Built with cutting-edge web technologies, it provides a seamless, cross-platform DOS emulation experience that works on desktop and mobile devices.

The project leverages js-dos v8.3.20, a WebAssembly-based DOS emulator that achieves 80-90% of native DOS performance. Combined with React 19's modern component architecture and Vite's lightning-fast build system, DosKit delivers an exceptional user experience for retro computing enthusiasts and developers.

## Features

### Core Features

- **Interactive DOS Prompt**: Boots directly to a fully functional DOS command prompt where users can execute DOS commands
- **Cross-Platform Compatibility**: Works seamlessly on Windows, macOS, Linux, iOS, and Android
- **Progressive Web App (PWA)**: Can be installed as a native app with full offline support
- **Deep Linking**: Load specific applications directly via URL parameters (e.g., `?app=secondreality`)
- **Offline Functionality**: Works completely offline after first visit thanks to service worker caching
- **WebAssembly Performance**: Leverages js-dos v8.3.20 for near-native DOS emulation speed
- **Full Keyboard Support**: All standard DOS keyboard inputs including function keys and special characters
- **Audio Support**: Sound Blaster and AdLib emulation with proper audio output
- **Responsive Design**: Optimized layouts for desktop, tablet, and mobile devices
- **Touch Controls**: Mobile-friendly on-screen keyboard for touch devices
- **Type-Safe Development**: Full TypeScript support with comprehensive type definitions
- **Service Worker Caching**: Intelligent cache management for fast loading

### PWA Features

- **Installable**: Install DosKit as a native app on desktop and mobile
- **Offline Support**: Works completely offline after first visit
- **Fast Loading**: Service worker caches assets for instant loading
- **Native Experience**: Standalone mode without browser UI
- **Auto-Updates**: Automatic updates when new versions are available
- **Connection Status**: Real-time online/offline indicator

## Architecture

### Component Hierarchy

```
App (Root)
├── ErrorBoundary
│   └── DosPlayerWithApps
│       ├── DemoSelector (modal)
│       │   └── App selection UI
│       ├── DosPlayer
│       │   └── js-dos emulator instance
│       ├── Loading overlay
│       └── Error overlay
├── OfflineIndicator
└── UpdateNotification
```

### Data Flow

1. **Application Loading**: User visits site → Service worker checks cache → Loads assets
2. **Emulator Initialization**: DosPlayer component mounts → js-dos library loads → DOSBox initializes
3. **User Interaction**: User types commands → js-dos processes input → DOSBox executes → Screen updates
4. **Deep Linking**: URL parameter detected → App configuration loaded → Emulator starts with app

### State Management

- React hooks (useState, useEffect, useCallback) for component state
- Context API for global state (error tracking, service worker updates)
- Local storage for user preferences and saved states
- URL parameters for deep linking state

## Installation & Setup

### Prerequisites

- Node.js 18+ (recommended: 24.4.1 or later)
- npm 9+ or yarn 1.22+
- Modern browser with WebAssembly support

### Installation Steps

1. Clone the repository:
```bash
git clone https://github.com/cameronrye/doskit.git
cd doskit
```

2. Install dependencies:
```bash
npm install
```

3. Start the development server:
```bash
npm run dev
```

4. Open your browser and navigate to `http://localhost:5173`

The DOS emulator will automatically load and present an interactive DOS prompt!

## Configuration

### DOSBox Configuration

DosKit uses DOSBox configuration files to customize the DOS environment. The default configuration is located in `src/config/dosbox.conf.ts`.

Example custom configuration:
```typescript
const customConfig = `
[cpu]
core=auto
cycles=max

[autoexec]
@echo off
echo Welcome to My DOS App!
mount c .
c:
myapp.exe
`;
```

### js-dos Options

Customize the emulator behavior with js-dos options in `src/config/jsdos.config.ts`:

Available options:
- `theme`: 'dark' or 'light'
- `volume`: 0.0 to 1.0
- `fullScreen`: Enable fullscreen mode
- `autoStart`: Auto-start emulator on load
- `backend`: 'dosbox' or 'dosboxX'
- `mouseCapture`: Auto-capture mouse input

### Mobile Configuration

DosKit automatically detects mobile devices and applies optimized settings:
- Larger touch controls
- On-screen keyboard with common DOS keys
- Optimized aspect ratio for mobile screens

## Usage

### Basic Usage

Visit https://doskit.net/ to use the emulator directly in your browser. The application boots to an interactive DOS prompt where you can execute DOS commands.

### Deep Linking

DosKit supports loading specific applications directly via URL parameters:

- Load Second Reality: `https://doskit.net/?app=secondreality`
- Load Impulse Tracker: `https://doskit.net/?app=impulsetracker`

Features:
- Shareable Links: URLs automatically update when you select an app
- Bookmarkable: Save direct links to your favorite DOS applications
- Browser Navigation: Back/forward buttons work correctly
- Refresh-Safe: Page refreshes maintain the loaded application
- Error Handling: Invalid app IDs show helpful error messages

### Adding DOS Applications

To run DOS applications or games:

1. Create a custom DOSBox configuration
2. Place your DOS files in the public directory or use the `initFs` option
3. Update the DosPlayer component with your configuration

### Programmatic Control

Access the Command Interface for programmatic control:

```typescript
import { useState } from 'react';
import { DosPlayer } from './components/DosPlayer';
import type { CommandInterface } from './types/js-dos';

function MyApp() {
  const [ci, setCi] = useState<CommandInterface | null>(null);

  const handleReady = (commandInterface: CommandInterface) => {
    setCi(commandInterface);
    // Control DOS programmatically
    commandInterface.simulateKeyPress(13); // Press Enter
  };

  return <DosPlayer onReady={handleReady} />;
}
```

Available commands:
- `ci.pause()` / `ci.resume()` - Control emulation
- `ci.mute()` / `ci.unmute()` - Audio control
- `ci.screenshot()` - Capture screen
- `ci.fsReadFile()` / `ci.fsWriteFile()` - File system access

## API Documentation

### DosPlayer Component

Main component for DOS emulation.

Props:
- `dosboxConf?: string` - DOSBox configuration
- `options?: DosOptions` - js-dos options
- `onReady?: (ci: CommandInterface) => void` - Callback when emulator is ready
- `onExit?: () => void` - Callback when emulator exits
- `className?: string` - CSS class name

### CommandInterface

Interface for controlling the DOS emulator programmatically.

Methods:
- `pause(): Promise<void>` - Pause emulation
- `resume(): Promise<void>` - Resume emulation
- `mute(): Promise<void>` - Mute audio
- `unmute(): Promise<void>` - Unmute audio
- `screenshot(): Promise<ImageData>` - Capture screenshot
- `fsReadFile(path: string): Promise<Uint8Array>` - Read file from DOS filesystem
- `fsWriteFile(path: string, data: Uint8Array): Promise<void>` - Write file to DOS filesystem
- `simulateKeyPress(keyCode: number): void` - Simulate key press
- `exit(): Promise<void>` - Exit emulator

## Deployment

DosKit is configured for automatic deployment to GitHub Pages with custom domain support.

### Quick Deployment

1. Enable GitHub Pages in repository settings (Settings → Pages → Source: GitHub Actions)
2. Push to main branch: `git push origin main`
3. Monitor deployment: Check the Actions tab
4. Visit your site: `https://doskit.net/`

The site automatically rebuilds and deploys on every push to `main`.

### Custom Domain Setup

1. Add CNAME file to public/ directory with your domain
2. Configure DNS records to point to GitHub Pages
3. Enable HTTPS in GitHub Pages settings

### Build Process

The build process includes:
1. Generate social media images from SVG sources

## Troubleshooting

### Common Issues

#### "DOS emulator library not loaded"
- Check internet connection
- Verify CDN is accessible
- Check browser console for errors
- Try refreshing the page
- Clear browser cache

#### Black Screen / Emulator Not Starting
- Check browser console for errors
- Verify WebAssembly support
- Try a different browser
- Disable browser extensions
- Check hardware acceleration

#### Poor Performance / Lag
- Reduce CPU cycles in DOSBox config
- Enable hardware acceleration
- Close other browser tabs
- Try different rendering backend
- Reduce screen resolution

#### Keyboard Not Working
- Click inside emulator window
- Check browser has focus
- Try clicking Play button
- Use on-screen keyboard on mobile
- Check console for errors

#### Audio Not Playing
- Audio automatically unmutes when ready
- Check browser audio not muted
- Verify volume setting in options
- Click inside emulator for user interaction
- Check DOSBox sound card configuration
