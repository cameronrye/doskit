## Overview

DosKit is a modern web application that enables users to run classic DOS applications and demos directly in their browser without any installation. Built with cutting-edge web technologies, it provides a seamless, cross-platform DOS emulation experience that works on desktop and mobile devices.

The project leverages js-dos v8.3.20, a WebAssembly-based DOS emulator built on DOSBox. Combined with React 19's modern component architecture and Vite's lightning-fast build system, DosKit delivers an exceptional user experience for retro computing enthusiasts and developers.

DosKit comes with a library of demoscene productions and music trackers, among them Second Reality, Crystal Dream 2, Impulse Tracker and Scream Tracker 3 (see Bundled Applications under Usage). Games are outside its scope.

## Features

### Core Features

- **Interactive DOS Prompt**: The start page boots a fully functional DOS command prompt where users can execute DOS commands, with the application selector open over it
- **Application Library**: Demoscene productions and music trackers, picked from a selector of floppy disks that works with the mouse or the keyboard (arrow keys, Enter, Space, Escape)
- **Cross-Platform Compatibility**: Works seamlessly on Windows, macOS, Linux, iOS, and Android
- **Progressive Web App (PWA)**: Can be installed as a native app, with offline support
- **Deep Linking**: Load specific applications directly via URL parameters (e.g., `?app=secondreality`)
- **Offline Functionality**: After the first visit the app and its DOS prompt work offline; each application works offline once it has been opened online
- **WebAssembly Performance**: js-dos v8.3.20 runs DOSBox as WebAssembly in a worker thread and renders with WebGL
- **Full Keyboard Support**: All standard DOS keyboard inputs including function keys and special characters
- **Audio Support**: Sound Blaster and AdLib emulation with proper audio output
- **Responsive Design**: Optimized layouts for desktop, tablet, and mobile devices
- **Touch Controls**: Mobile-friendly on-screen keyboard for touch devices
- **Type-Safe Development**: Full TypeScript support with comprehensive type definitions
- **Service Worker Caching**: Emulator files and application archives stay cached across deploys until js-dos or the archives change

### PWA Features

- **Installable**: Install DosKit as a native app on desktop and mobile. Where the browser offers installation, DosKit suggests it 5 seconds after load, waits 7 days after each dismissal, and stops asking after the third
- **Offline Support**: After the first visit the app works offline (see Service Worker under Architecture)
- **Fast Loading**: Service worker caches assets for instant loading
- **Native Experience**: Standalone mode without browser UI
- **Update Prompt**: DosKit checks for a new version every hour and whenever the tab becomes visible again. Once one has installed, it offers to reload into it ("Update Now") or to wait ("Later"); an update put off is offered again on the next visit
- **Connection Status**: Real-time online/offline indicator

## Architecture

### Component Hierarchy

```
ErrorBoundary (main.tsx)
└── App
    ├── OfflineIndicator (offline and back-online notices, install prompt)
    ├── Header (current application, Change Application button)
    ├── URL error banner (unknown ?app= id)
    ├── ErrorBoundary
    │   └── DosPlayerWithApps
    │       ├── DemoSelector (modal)
    │       │   └── App selection UI
    │       ├── Loading overlay
    │       ├── Error overlay
    │       └── DosPlayer (useDosEmulator hook + DosPlayerUI)
    │           └── js-dos emulator instance
    └── Footer (Ready/Loading and Online/Offline badges)
```

UpdateNotification is not part of this tree: src/utils/updatePrompt.ts mounts it in a React root of its own when a new service worker is waiting.

### Data Flow

1. **Application Loading**: User visits site → Service worker serves the page from the network, or from its cache when offline → Loads assets
2. **Emulator Initialization**: DosPlayer component mounts → useDosEmulator starts js-dos with the merged options → js-dos loads the DOSBox backend from /emulators/ → DOSBox initializes with the DOSBox configuration
3. **User Interaction**: User types commands → js-dos processes input → DOSBox executes → Screen updates
4. **Deep Linking**: App id read from `?app=` or the path → URL rewritten to `/?app=<id>` → DosPlayerWithApps downloads the app's ZIP archive and DOSBox configuration → Emulator starts with app, without booting the default prompt first
5. **Selecting an App**: User picks an app in DemoSelector → its archive downloads with progress, cancellable and with a 30-second timeout → DosPlayerWithApps remounts DosPlayer with the files → the URL becomes `/?app=<id>` in a new history entry

### State Management

- React hooks (useState, useEffect, useCallback) for component state, held in App and DosPlayerWithApps and passed down as props; there is no context or global store
- Local storage only for install prompt dismissals, through src/utils/storage.ts, which never throws when storage is blocked or full
- URL parameters for deep linking state

### Service Worker

`public/sw.js` is registered in production builds only:

- **Install**: precaches the app shell (/, /index.html, the manifest, logo and favicon, js-dos.js and js-dos.css), every JS and CSS bundle, including the lazily loaded app configs, and the DOSBox backend (wdosbox, wlibzip and emulators.js)
- **Pages**: network first with a 5-second timeout, falling back to the cached page or to index.html, so deep links open offline too
- **Emulator files** (`/emulators/`): cache first, from a cache named after the js-dos version, which deploys keep; DOSBox-X is not precached and is stored on first use
- **Application archives** (`/demos/*.zip`): cache first, from a cache named after a hash of the archives, which deploys keep while the archives stay the same; each is stored on first use
- **Other assets**: stale-while-revalidate, in a cache of at most 100 entries that trims the least recently used, never the precached files
- **Updates**: each new build installs as a new worker, which waits until the user accepts the update prompt

### Error Handling

- **Error boundaries** around the whole app (main.tsx) and around the player (App.tsx), which report to the error tracker
- **Global handler** (src/utils/globalErrorHandler.ts): logs uncaught errors and unhandled promise rejections, and keeps known harmless ones out of the console: js-dos's fullscreen and keyboard lock calls that fail without a user gesture, ResizeObserver loop notices and browser extension errors
- **Error tracking** (src/utils/errorTracking.ts): a console tracker; no remote service is set up
- **Downloads**: application archives retry network failures and 408, 429, 500, 502, 503 and 504 responses up to three times with exponential backoff; a download the user cancels, or a newer navigation supersedes, is not reported as an error
- **Messages**: the selector explains a failed or timed-out load, an unknown `?app=` id shows a banner, a deep link that fails to load offers Try Again (back to the selector), and the player offers a reload when js-dos cannot start

## Installation & Setup

### Prerequisites

- Node.js 24 or later (package.json engines; the version is in .nvmrc)
- npm (the repository's lockfile is package-lock.json)
- Modern browser with WebAssembly support

### Installation Steps

1. Clone the repository:
```bash
git clone https://github.com/cameronrye/doskit.git
cd doskit
```

2. Install dependencies:
```bash
npm install
```

3. Start the development server (it first copies the js-dos runtime from node_modules into public/):
```bash
npm run dev
```

4. Open your browser and navigate to `http://localhost:5173`

The DOS emulator will automatically load and present an interactive DOS prompt, with the application selector open over it!

The service worker is only registered in production builds: to try offline behavior, run `npm run build` and `npm run preview`.

## Configuration

### DOSBox Configuration

DosKit uses DOSBox configuration files to customize the DOS environment. The default configuration, which the DOS prompt boots with, is located in `src/config/dosbox.conf.ts`; each application builds its own in its config module in `src/dos-apps/`, starting from a preset in `src/utils/dosboxConfigBuilder.ts`.

js-dos's default DOSBox backend ignores settings it does not have without a warning, such as `core=dynamic`, a 486 or Pentium `cputype`, `[dos] ver` or a `[memory]` section; `src/dos-apps/README.md` lists them.

Example custom configuration:
```typescript
const customConfig = `
[cpu]
core=auto
cycles=max

[autoexec]
@echo off
echo Welcome to My DOS App!
mount c .
c:
myapp.exe
`;
```

### js-dos Options

Customize the emulator behavior with js-dos options in `src/config/jsdos.config.ts`. DosKit's defaults: the DOSBox backend in a worker thread with OffscreenCanvas, WebGL rendering at a 4:3 aspect ratio, volume 0.7, autoStart with no countdown, js-dos cloud features off (`noCloud`), and emulator files from `/emulators/`.

Available options:
- `theme`: 'dark' or 'light'
- `volume`: 0.0 to 1.0
- `fullScreen`: Enable fullscreen mode
- `autoStart`: Auto-start emulator on load
- `backend`: 'dosbox' or 'dosboxX' (DosKit's DOSBox configurations are written for 'dosbox')
- `mouseCapture`: Auto-capture mouse input
- See `src/types/js-dos.d.ts` for the complete options

### Mobile Configuration

DosKit detects mobile devices by their user agent and applies optimized settings:
- Larger touch controls
- On-screen keyboard with common DOS keys (Esc, function keys, digits, letters, Ctrl, Alt, Space, Enter and the arrow keys)

### Deep Linking

DosKit supports loading specific applications directly via URL parameters:

- Load Second Reality: `https://doskit.net/?app=secondreality`
- Load Impulse Tracker: `https://doskit.net/?app=impulsetracker`

Features:
- Shareable Links: URLs automatically update when you select an app
- Bookmarkable: Save direct links to your favorite DOS applications
- Browser Navigation: Back/forward buttons work correctly
- Refresh-Safe: Page refreshes maintain the loaded application
- Error Handling: Invalid app IDs in `?app=` show helpful error messages
- One URL Form: path-style links (`https://doskit.net/secondreality`) and other spellings (`?app=second-reality`) open the same app, and the address bar is rewritten to `/?app=secondreality`
- Direct Start: a deep link downloads its application and starts it without booting the default prompt first

### Adding DOS Applications

An application in the selector is three pieces, and `src/dos-apps/README.md` walks through each:

1. A ZIP archive of the program's files at `public/demos/<id>.zip`
2. A config module, `src/dos-apps/<id>.config.ts`, with the archive's URL and the DOSBox configuration, built from a preset in `src/utils/dosboxConfigBuilder.ts`
3. An entry in `availableApps` in `src/config/apps.config.ts`, which imports the config module lazily

`npx vitest run src/config/apps.config.test.ts` checks every registered application. Only add programs you may redistribute.

### Programmatic Control

Access the Command Interface for programmatic control:

```typescript
import { useState } from 'react';
import { DosPlayer } from './components/DosPlayer';
import type { CommandInterface } from './types/js-dos';

function MyApp() {
  const [ci, setCi] = useState<CommandInterface | null>(null);

  const handleReady = (commandInterface: CommandInterface) => {
    setCi(commandInterface);
    // Control DOS programmatically
    commandInterface.simulateKeyPress(13); // Press Enter
  };

  return <DosPlayer onReady={handleReady} />;
}
```

Available commands:
- `ci.pause()` / `ci.resume()` - Control emulation
- `ci.mute()` / `ci.unmute()` - Audio control
- `ci.screenshot()` - Capture screen
- `ci.fsReadFile()` / `ci.fsWriteFile()` - File system access

## API Documentation

### DosPlayer Component

Main component for DOS emulation. It starts js-dos once per mount and stops it on unmount, so give it a new `key` to run something else.

Props:
- `dosboxConf?: string` - DOSBox configuration (default: the DOS prompt's, from `src/config/dosbox.conf.ts`)
- `options?: Partial<DosOptions>` - js-dos options, merged over the defaults in `src/config/jsdos.config.ts`
- `onReady?: (ci: CommandInterface) => void` - Callback when emulator is ready
- `onExit?: () => void` - Callback when a ready emulator is gone, because DOS exited or unmounting stopped it; called once per onReady
- `className?: string` - CSS class name
- `style?: React.CSSProperties` - Inline styles

### CommandInterface

Interface for controlling the DOS emulator programmatically (the full interface is in `src/types/js-dos.d.ts`).

Methods:
- `pause(): void` - Pause emulation
- `resume(): void` - Resume emulation
- `mute(): void` - Mute audio
- `unmute(): void` - Unmute audio
- `screenshot(): Promise<ImageData>` - Capture screenshot
- `fsReadFile(file: string): Promise<Uint8Array>` - Read file from DOS filesystem
- `fsWriteFile(file: string, contents: ReadableStream<Uint8Array> | Uint8Array): Promise<void>` - Write file to DOS filesystem
- `persist(onlyChanges?: boolean): Promise<Uint8Array | null>` - Pack the DOS filesystem, or only its changes, into a bundle
- `simulateKeyPress(...keyCodes: number[]): void` - Simulate key presses
- `exit(): Promise<void>` - Exit emulator

## Deployment

DosKit is configured for automatic deployment to GitHub Pages with custom domain support.

### Quick Deployment

1. Enable GitHub Pages in repository settings (Settings → Pages → Source: GitHub Actions)
2. Push to main branch: `git push origin main`
3. Monitor deployment: Check the Actions tab
4. Visit your site: `https://doskit.net/`

The site automatically rebuilds and deploys on every push to `main`, once the CI jobs (lint, format check, type check, tests and build) pass.

### Releases

release-please keeps a release pull request open from the conventional commits on `main`. Merging it bumps the version in package.json, adds the release to CHANGELOG.md and publishes a GitHub release, to which the release workflow attaches a ZIP of the build.

### Custom Domain Setup

1. Add CNAME file to public/ directory with your domain
2. Configure DNS records to point to GitHub Pages
3. Enable HTTPS in GitHub Pages settings

### Build Process

The build process (`npm run build`) includes:
1. Copying the js-dos runtime from node_modules into public/ (scripts/copy-js-dos.js, run as prebuild)
2. TypeScript type checking of the app, the config files and the tests (`tsc -b`)
3. Vite production build with code splitting (each application's config module is a chunk of its own, and so is React), asset optimization and minification
4. 404.html, written as a copy of index.html, so that GitHub Pages boots the app for path-style deep links such as /secondreality
5. Service worker version injection (scripts/inject-sw-version.js): a new cache version for every build, the js-dos version and a hash of the application archives, which name the caches deploys keep, and the list of bundles to precache. The build fails if the worker would precache a file that is not in dist/.

The social media images are not part of the build: after editing their SVG sources, run `npm run generate-social-images` and commit the PNGs.

## Troubleshooting

### Common Issues

#### "DOS emulator library not loaded"
- js-dos.js comes from DosKit's own site (/js-dos.js), not a CDN: check the browser console and network panel for that request
- Check internet connection
- Try refreshing the page
- Clear browser cache
- In a local checkout, `npm run dev` and `npm run build` copy js-dos into public/ first; if that step reports that js-dos is not installed, run `npm ci`

#### Black Screen / Emulator Not Starting
- Check browser console for errors
- Verify WebAssembly support
- Try a different browser
- Disable browser extensions
- Check hardware acceleration

#### Poor Performance / Lag
- Reduce CPU cycles in DOSBox config
- Enable hardware acceleration
- Close other browser tabs
- Try different rendering backend
- Reduce screen resolution

#### Keyboard Not Working
- Click inside emulator window
- Check browser has focus
- Try clicking Play button
- Use on-screen keyboard on mobile
- Check console for errors

#### Audio Not Playing
- Audio automatically unmutes when ready
- Check browser audio not muted
- Verify volume setting in options
- Click inside emulator for user interaction
- Check DOSBox sound card configuration

#### Application Fails to Load
- Check internet connection: downloads retry network failures up to three times, and the selector gives up after 30 seconds
- Offline, only applications that have been opened online before can load
- After a failed deep link, Try Again returns to the selector, where the application can be picked again

### Debug Mode

Enable detailed logging in development:
```typescript
import { logger } from './utils/logger';
logger.debug('MyComponent', 'Debug message');
```

The logger prints every level, with timestamps, in development; production builds keep warnings and errors.
